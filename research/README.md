# FVG Confluence Lab (local research prototype)

This runs the Next.js Moneyprinter UI locally with a Python 3 scoring process. No VPS, machine learning, automated orders, or broker account integration is needed. XAU/USD is the only live source. The prototype is not a trading system and scores are not calibrated probabilities.

## Run on your own computer

1. Install Node.js 20+ and Python 3.10+ (Python uses only its standard library). Open this repository in VS Code and run `npm install`.
2. Revoke the OANDA token previously shared in chat; create a new practice token. Do not paste it into the repository, browser, a notebook, logs or chat. Set it only in the terminal environment.
3. Enable the local bridge and start Next from the same terminal. In macOS/Linux:

```sh
export RESEARCH_LOCAL_ENABLED=1
export OANDA_API_TOKEN='YOUR_NEW_PRACTICE_TOKEN'
npx next dev --hostname 127.0.0.1 --port 3000
```

PowerShell:

```powershell
$env:RESEARCH_LOCAL_ENABLED='1'
$env:OANDA_API_TOKEN='YOUR_NEW_PRACTICE_TOKEN'
npx next dev --hostname 127.0.0.1 --port 3000
```

4. Open `http://localhost:3000/admin/research`. Do not expose or forward this development server to the internet. If Supabase auth is configured, sign in. Without OANDA, select synthetic demo data, which is visibly marked and is not gold.
5. Use OANDA practice only after verifying your account's eligibility and token. The prototype retrieves the most recent 100–50,000 completed midpoint candles, paging backwards through OANDA in requests of at most 5,000 each. Actual history depends on provider availability; the UI reports the returned date range and warns if fewer are returned. The app does not yet support an arbitrary date range or more than 50,000 candles per run. OANDA provides M1, M5, M15, M30, H1, D and W natively. The 3-minute chart is aggregated from three complete consecutive M1 bars in UTC-aligned buckets; OANDA does not provide M3 natively. The 45-minute chart is built from three complete, consecutive M15 bars using UTC-aligned 45-minute buckets; incomplete groups are excluded, and boundaries may differ from other platforms. A 45m run needs approximately three times as many 15m candles and may take longer. Large downloads and local snapshots may take time and disk space. It does not submit orders.

The bridge is disabled unless explicitly enabled, and rejects non-local Host and mismatched Origin. These header checks are not a substitute for binding the server to loopback; do not use npm run dev (which binds to all interfaces) for this feature. The OANDA token stays on the server process, not the browser. Use local development only; do not add this token to deployed environment variables. API credentials should be revoked immediately if exposed.

## Automatic older history

OANDA starts with 5,000 candles by default. As you pan near the left edge, the app requests up to 5,000 older completed candles at a time from the oldest candle in the existing local snapshot, deduplicates the boundary, and prepends them. It keeps the selected candle and viewport in place, recomputes the scoring and backtest using the stored settings from the original run, and stops when OANDA returns no more data or the 50,000-candle per-run cap is reached. A network error can be retried. The 45-minute chart is built from 15-minute source bars, so it can require three times as many requests. Automatic history is not enabled for synthetic demonstration data.

Adding history can change calculations at existing candles because they now have more prior context, and it moves the exploratory 60/20/20 split. Each expanded run is saved as another snapshot and uses local disk space. Neither its displayed test partition nor a manually tuned result should be treated as a genuinely untouched final test. Dataset expansion does not update the newest/live candles; use Load & analyse for a fresh snapshot.

## What this prototype does

- Produces a zoomable candlestick chart for the latest completed 1m, 3m, 5m, 15m, 30m, 45m, 1h, daily or weekly bars. Click a candle to see the causal score. Use **Maximize chart** (or Esc to exit) for browser fullscreen. Active FVG boundaries at the selected candle are shown as dashed lines.
- Implements the existing three-candle strict FVG rule, with confirmed bars and no FVG through missing bars. This is a Python reimplementation, not execution of the Free Chart JavaScript.
- Daily and weekly OANDA candles use its New York 17:00 alignment, with Friday weekly alignment. Because the current scorer and indicator gap handling assume fixed-duration, continuously aligned intraday candles, daily/weekly are chart-only: scores, backtests and custom indicators are disabled rather than displaying misleading values.
- 8 adjustable weights (total 100), simple confirmed pivots, close-through BOS/CHoCH, swing reclaims, ATR body size, FVG presence/status, midpoint positioning, candle direction, and fixed UTC London/NY context. MTF/HTF are built from complete groups of 3/12 execution bars and compared using simple high/low logic. Only completed aggregates are used. It is NOT yet the complete specification: FVG displacement/alignment scoring, delayed reclaims, range options, timezone/DST, nuanced candles, liquidity magnitude and full MTF structure remain to be built.
- Requires a recent directional structure break or sweep alongside a directional candle for hypothetical entries. Simulated close entry, ATR stop, fixed R target, non-overlapping trades, flat round-trip price cost, excluding ties, missing-data gaps and timeouts. No accurate bid/ask fills, intrabar ordering, variable spread, commission model, margin, financing or market impact. Win rate counts target hits before costs; P&L subtracts cost. Take care: cost/round-trip assumptions can materially affect results.
- The displayed 60/20/20 chronological segments are exploratory. Because the UI shows all three results on each run, the Test segment is NOT a genuinely untouched final test after repeated tuning. Preserve a separate unseen period/data file and freeze model and settings before final evaluation. No automated tuning or ML exists here yet.
- Each run stores the downloaded candle snapshot, its SHA-256, configuration, per-candle scoring explanations, and backtest summary in `research/data/runs.sqlite3` on the local machine. Snapshots contain future candles, but per-candle score features do not intentionally use future data. Do not commit this local database. Loaded datasets and settings can be exported from the interface, but the SQLite history has no browser yet.
## Custom indicator editor

Load candles and choose **FVG Reaction Study** from the chart’s Indicator selector to display the built-in study. Open **Custom indicator** to adjust its settings, or paste/upload another Free Chart inputs JSON array and JavaScript factory body. Press **Compile & show** and adjust the generated controls. Remove it with **Remove indicator**. Scripts run only in a disposable browser worker inside an opaque-origin sandboxed iframe with a restrictive network CSP and a 3-second timeout; they do not run in Python or on the server. This reduces risk, but browser sandboxing is not a security guarantee: use scripts you trust and keep your browser updated.

The built-in study uses the supplied definitions: a bullish grab closes in or below the FVG; a bullish sweep touches it but closes above it, with mirrored bearish rules. The study is visual only and does not change the separate Python scoring engine. Its normal-approximation confidence margin can be misleading for small or dependent samples (including zero-width intervals at 0% or 100%); 50% is not a validated market baseline.

This is a **compatibility subset**, not the full Free Chart runtime. Implemented: `calc`, `draw`, input defaults, `bool`, `int`, `float`, `color`, `select`, `session`, `string`, `time`, `source`, and `bv.bounds`, `visible`, `visibleBars`, `xOfIndex`, `yOfPrice`, `halfBar`, `precision`, `priceText`, `clamp`, `syminfo`, `parseClock`, `detectBarMs`, `withAlpha`, `text`, `label`, `line`, `box`, and `ma` (SMA/EMA/RMA/WMA). The worker supports raw `ctx` and simple axes. Under-candle compositing, advanced autoscaling, alerts, plotted figures, additional Free Chart helpers and perfect pixel parity are not implemented. Unsupported calls show an error.

Rendering is a separate transparent overlay and may look different from Free Chart, particularly backgrounds, text, chart margins and volume charts. The latest completed candle is still passed as the last bar; scripts that treat the last bar as live will lag one candle. Imported scripts see the entire loaded dataset even when you click a historical candle: they may repaint or use future candles. They **do not affect the Python scores or backtests**. Do not assume the imported indicator is causal. Script and settings remain in page memory and are not saved on reload.

## Tests
`python3 -m unittest discover -s research -p 'test_*.py'`. Tests include changing future candles and checking prior scores are unchanged. They are not proof of absence of every form of bias; validate with independent data before drawing conclusions.


## Replay and suggestion win-rate checker

Load an intraday chart, click **Backtest** in its header, click a past candle, and choose **Start at selected candle**. Play, pause, step and speed controls work in fullscreen. Only candles through the current replay cursor are supplied to the chart and indicator; analysis uses the causal scores calculated for that completed candle. Reset before picking another start or changing simulation parameters. Backward history loading is paused while the replay panel is open.

The prototype proposes one pending or open trade at a time when the existing heuristic score reaches the selected threshold and a matching, fresh three-candle FVG with a direction-matching middle candle lies beyond the close. Entry is the near FVG edge, the stop is beyond its far edge plus an ATR buffer, and the target is fixed R. A pending limit can fill by touch on a subsequent candle, expire or cancel on an opposing score. A position resolves on the first later stop/target touch. If entry and exit occur in one bar, both exits occur in one bar, a relevant gap occurs, or the hold limit expires, the outcome is excluded; OHLC data cannot determine the sequence or actual execution. The round-trip price cost reduces net R; it is not a spread/slippage execution model. Wins and losses are gross target/stop hits, not net-profit classification. Pending and open positions are not completed trades.

Recent same-direction outcomes in *this replay* are displayed only after 30 resolved trades (up to the latest 100); this is a descriptive sample, not a calibrated probability or learning algorithm. Parameters are fixed for the run. The suggestion win rate is **not** the FVG study's grab/sweep outcome rate. The selected FVG indicator has separate event statistics, and its adjustable study inputs do not control this prototype strategy. The main suggestion scorer remains separate and uses simplified structure/bias and liquidity-reclaim heuristics, not the no-wick engine, independently confirmed order blocks, or a trained model. It does not consume live prices, place orders, learn automatically, or guarantee improvement. Test later periods separately and retain excluded counts when assessing results.


### Chart indicators and navigation

The indicator selector includes **No-Wick Structure**, with the supplied internal/external protected-level definitions and input settings available from the chart, including fullscreen. Tick size defaults to 0 for decimal-based auto-detection; set it manually if necessary. The local adapter processes the final loaded candle because this chart contains completed candles, unlike the supplied Free Chart script which treats its last bar as live. The indicator is visual only: no alert delivery or orders. Its own simulated statistics use different assumptions from the replay checker (including counting same-bar TP/SL ties as losses). Do not treat those figures as validated backtest results. The indicator does not currently feed the suggestion scorer.

During replay, drag the chart to inspect prior candles; dragging turns off automatic following. Select **Follow latest** to recenter and resume following. While dragging or scaling, the existing indicator image is temporarily transformed to track chart movement and redrawn after movement stops. Depending on chart size and indicator complexity, newly exposed drawing areas or fixed indicator tables can briefly reposition until the redraw finishes.


### FVG quick simulation and zone analysis

Select **FVG Reaction Study**, choose the candle to use as the point-in-time cutoff by clicking outside a zone, and open **Parameters** in its chart legend. In replay, the cutoff follows the replay candle instead. Set target R, stop method (last confirmed opposing swing, FVG boundary, or ATR), stop buffer, swing confirmation length, holding window, recent-history window, displacement and MSS filters, and round-trip cost. Click **Quick simulation test**. Click a displayed FVG box to see that zone’s attributes and its result known by the cutoff. The recent-history window defaults to 5,000 and is capped at 10,000 candles; swing and ATR warmup uses the earlier loaded prefix.

The quick study adopts the FVG study’s direction, middle-candle, gap-size, ATR-length, age, and visibility settings. Middle-candle displacement is its absolute body divided by ATR on that candle: low <1, medium 1 to <1.5, high ≥1.5. The category filter can select these groups; the fixed boundaries are illustrative, not validated market regimes. MSS uses the same protected-level structure engine as the No-Wick study, with its own configurable swing length. A close through the protected high or low flips the trend on that bar; an FVG is classified as an MSS formation when that shift occurs on its middle or formation candle. The simulation swing length follows the No-Wick internal length when it is changed (within the simulation’s 1–30 range); it can also be adjusted separately in Parameters. The structure engine follows the supplied script through gaps; gap-affected simulated trades are excluded separately.

The simulation hypothesizes a limit fill on the first touch of the FVG near edge after formation. Swing stops use only levels confirmed before the touch bar. Same-bar entry/exit, both exit levels in one bar, gaps, timeouts, and invalid stops are excluded; pending outcomes are not in the win-rate denominator. Overlapping zones are tested independently. Grab/sweep classification uses the touch candle’s eventual close, so the table groups are *retrospective conditional summaries*, not executable grab-filter strategies. Cost affects net R, not target-hit rate. The selected MSS-zone panel shows prior same-direction MSS FVG outcomes reaching ±1 formation ATR first within the chosen holding window, restricted to outcomes known by the selected zone’s formation. It shows a rate only with at least 30 resolved examples; related FVGs are not independent. This is a historical frequency, not a calibrated probability or forecast. No live feed, broker fills, slippage model or auto-improvement is provided.

### FVG context and separate entry scenarios (phase 1)

The selected-zone panel distinguishes closes inside the zone, rejection back beyond the near edge, and invalidation beyond the far edge, while retaining the FVG study's legacy grab/sweep label. Retest penetration is measured from the near edge toward the far edge and capped at 100%; close location is not capped. Retest body, upper/lower wick divided by same-bar ATR and close position within the candle are descriptive after-close values. The study analyses the first qualifying touch of each FVG only; prior touches are therefore zero by definition, not a claim about other untracked zone visits. It shows internal/external structure at formation and retest, MSS between them, middle-candle structure break, FVG height/ATR and bars to first touch. External/internal swing lengths are separate and follow the corresponding No-Wick settings within the simulation limits when those settings are changed.

The approach figure is the preceding five closes' net travel toward the FVG divided by the ATR available before the retest; a negative value means movement away. The 20-bar close-path efficiency ratio is absolute net close change divided by the sum of absolute close changes; <0.3 is labelled choppy, 0.3–<0.6 mixed, ≥0.6 directional. These are illustrative heuristics, not calibrated market regimes. The 20-bar high/low at retest is a reference. Choppiness never silently changes stop or target; the panel notes when a confirmation target lies beyond that observed range. The range and efficiency include the retest candle and cannot be known at an earlier intrabar touch.

Touch and confirmation are tested independently. Touch assumes a fill at the near edge and excludes the bar if an exit is also touched on that bar. The confirmation alternative requires a direction-matching retest candle close at or past the zone midpoint without far-edge invalidation, enters at the next candle's open and does not assume a fill on the previous candle. On the open-entry candle a single exit can be evaluated after the open, but a candle touching both exits is excluded. Gaps, invalid stops/targets, same-bar ambiguity and timeouts remain excluded. A retest-extreme stop is unavailable to a touch entry because that extreme is not yet known; it is available after a confirmed retest. The card compares buffered FVG, retest, protected, prior confirmed swing and ATR stops, but only the method chosen in Parameters is simulated. Invalid or wrong-side stops are not usable. A provisional pre-touch plan uses levels known at the selected close and is not a fill.

Targets may be fixed-R or the latest confirmed opposing swing known at entry; if no valid opposing swing exists, that target is unavailable. This is not a full liquidity map or necessarily the nearest of all historical levels. The card warns if the known opposing swing lies before the fixed-R target. Round-trip cost is other cost + spread + twice per-side slippage, all in price units. This is a P&L deduction, not an executable bid/ask or fill-price model; win rate remains gross target/stop hits. Results are separated by entry mode, direction and final retest close location. Grouping touch trades by the retest close is retrospective, not a tradable entry-time filter. Future clustering and calibrated probability estimates are not implemented in phase 1.

### Information guide and FVG condition groups

Use the **information** icon beside the FVG Confluence Lab title, or the chart-header information icon in fullscreen, to read the metric definitions and simulation limitations. When FVG Reaction Study is selected, the chart's upper-right **FVG condition groups** panel replaces the study's original statistics table by default. The original table remains available through FVG indicator settings; enabling both can overlap them. During replay, groups move to the lower right and update through the replay candle. The panel can be collapsed to reduce calculation and screen clutter.

Groups are deterministic, human-readable condition buckets—not machine-learning clusters. Direction and retest close classification are mandatory; optional factors include displacement, internal/external alignment at retest, choppiness, depth, gap size, approach, reaction close, and zone age. Disabling a factor combines its subgroups; more factors fragment samples. The group panel uses the quick-simulation parameter settings and visible direction filters, and can report touch or next-open confirmation scenarios separately. It shows resolved wins/losses, gross hit rate, average net R, excluded and open counts, and confirmation setups with no signal. Fewer than 30 resolved is labelled a small sample; 30 is a warning threshold, not proof of reliability. Overlapping zones are not independent. Because retest features and final close are known only after the retest candle, touch-entry groups are retrospective and cannot be used as executable touch-time filters.

A selected FVG's comparison excludes that FVG, but can include other outcomes resolved after the selected FVG formed, as long as they are known by the currently selected chart candle. It is descriptive as-of-now information, not an estimate available at the selected setup's formation. Neither the win rates nor average R are predictions. Overlapping outcomes, excluded trades, small samples, costs, regime change and optimizing on the same data can all distort results; assess any future rule on untouched chronological data.

**Groups CSV** downloads the aggregate buckets, counts, current grouping choices, FVG study settings and simulation settings. **Events CSV** downloads the individual first-touch observations and selected entry mode with feature values, simulated prices and outcomes. It records the formation and retest candle timestamps, the time retest features are known (end of retest candle), the entry bar and entry-time precision (touch fills have unknown intrabar timing), and the conservative outcome-known time (end of the resolution candle); open or waiting results have no resolution timestamp. Candle opens and closes are UTC. These are local browser downloads, not an automatically persisted database or trained model. Historical feature/outcome timestamps must be respected in future research to prevent look-ahead.

### Experimental Institutional Triad v2

The Triad profile uses `triadResearch.ts` and is research-only. It requires OANDA tick volume (older snapshots without volume and synthetic examples will not generate Triad trades); it does not send orders. It uses No-Wick internal protected structure with fixed length 3, 200 EMA direction, a simple 14-bar tick-VWMA/200 EMA reaction, directional candle close, and protected swing stop. First FVG retests are logged, not required by the default mode. This simple VWMA is not the chart's custom smoothed/proxy indicator. The 2.5x prior-20-bar true-range shock guard pauses new decisions for 20 minutes after the shock candle closes; it cannot predict CPI/PPI and is not a news calendar. The 15m/30m results are too small to validate the strategy.

For Triad, market fills are estimated at the next bar open with a constant spread, entry-bar exits are evaluated, both-hit bars are conservatively treated as losses and flagged, and gaps through stops use the open. Fixed lot size is a cap and is reduced or rejected to respect the planned risk limit; gaps can exceed it. Closed-balance drawdown excludes open equity drawdown and the engine does not model actual bid/ask history, slippage, margin, commissions or financing. Only this profile uses the revised engine. Other sniper profiles are legacy and still have the execution and accounting issues identified in the audit; do not infer they were validated. Old cached OANDA snapshots lack volume and must be reloaded. Unit tests: `node research/test_triad_v2.cjs`; research runner `node research/run_triad_oanda.cjs` requires private local snapshots.

#### 15-minute confluence research and decisions

Triad now defaults to the MA-reaction entry trigger; FVG retest is logged but never required by that default. The confluence study compares eight explicit modes, all conditioned on the same session/trend/EMA/risk gates. The simple previous-candle continuation proxy is **not** the full 11-step Moneyprinter Pullback Strategy. The UI's Decision checklist & near misses shows the latest decision and exports up to the latest 5,000 visited candles; earlier rows are counted as dropped. `signal` means a plan, not a confirmed fill; a null check means not evaluated. Check timestamps are candle-close decision times. For the audit see `reports/triad-confluence-research.md`; `node research/study_triad_combinations.cjs` requires the private local OANDA snapshot. The outlier guard is not a CPI/PPI calendar.
